# Web 프론트엔드 과제

본 프로젝트는 퍼플영(Purple Young) 프론트엔드 개발자 채용 과제를 위한 스타터 키트입니다.

## 🚀 시작하기

1. **공통 환경 구성 (필수)**
   - 본 과제는 로컬 Mock API 서버 연동이 필수입니다.
   - **[루트 디렉토리의 README.md](../README.md)**에 기술된 `[STEP 0] 공통 환경 구성` 가이드에 따라 Docker 서버를 먼저 구동해 주세요.

2. **의존성 설치 및 실행**
   - `web-kit` 폴더에서 실행합니다.
   ```bash
   npm install
   npm run dev
   ```

3. **접속**
   - http://localhost:3000 (또는 설정된 포트)에서 확인

## 🎯 과제 전형 요구사항

> **안내사항**: 본 과제는 제공되는 저장소 루트의 `mock-api` (Docker 환경)를 구동하여 연동해주시면 됩니다. 구현의 정확성뿐만 아니라 아키텍처 성숙도, 예외 처리, 그리고 렌더링 최적화 역량을 중점적으로 평가합니다.

### 1️⃣ 피드 및 미디어 렌더링
- [ ] **메인 피드**: 제공된 1,000개의 아이템 리스트를 효율적으로 렌더링 **(Pagination 또는 무한 스크롤 필수)**
- [ ] **미디어 카드**: 피드 아이템의 `thumbnail`과 `videoUrl`을 판단하여 적절한 미디어(이미지/비디오) 형태로 출력
- [ ] **인터랙션**: 좋아요(`PATCH /items/:id/like`) 및 조회수(`PATCH /items/:id/view`) 증가 기능 API 연동

### 2️⃣ 필터링 및 상태 동기화
- [ ] **태그 쿼리 검색**: 특정 태그 클릭 시 해당 태그를 포함한 아이템만 필터링 (`GET /items?tag=...`)
- [ ] **라우터 동기화**: 필터링 상태가 URL 쿼리 파라미터와 동기화되어, 페이지 새로고침 시에도 기존 상태가 유지(Hydration)되어야 함

### 3️⃣ 게시물 생성 및 파일 전송
- [ ] **미디어 업로드**: 파일 업로드 API(`POST /upload`)를 활용한 실제 Multipart 폼 업로드 및 새 게시물 등록 기능

### ✨ 4️⃣ 지원자 자율 기능 추가 (3개 이상 필수)
- [ ] **자율 기능 구현**: 본 서비스의 가치를 높일 수 있는 새로운 기능 또는 UX 개선 사항을 **3가지 이상** 자유롭게 제안하고 구현해 주세요. (예시는 제공하지 않으며, 지원자의 창의성과 프로덕트 감각을 평가합니다.)
- [ ] **구현 근거 기술**: 각 기능의 **기획 의도**와 이를 실현하기 위해 사용한 **기술적 핵심 포인트**를 README에 상세히 기록해 주세요. (이 과정이 변별력의 핵심입니다.)
- [ ] **📝 문서화 의무**: `README.md`를 필수 작성하여 로컬 실행 방법 및 본인의 렌더링 최적화/아키텍처 설계/자율 기능 구현 의도를 논리적으로 기술해 주세요.
- [ ] **🚨 에러 방어 로직**: 미디어(업로드) API 응답 URL 포트 분리 상황(Broken Image, 404 에러 등)에 대응하는 안전한 UI 방어 처리 (의도된 시스템 트랩)
- [ ] **🚀 성능 최적화**: 본인이 자신 있는 글로벌 상태 관리 도구 전역 셋업 및 과도한 리렌더링 방어 기법 적용
